# AWS ネットワーキング 学習カリキュラム

VPC を「設定項目を暗記している状態」ではなく「なぜその設定が必要なのかを説明できる状態」にすることをゴールとする。
ネットワークの一般知識が薄い前提で、Phase 1 で土台を作ってから AWS の話に入る。

**最終的なゴール:** マルチアカウント / オンプレ接続 / SaaS 提供 のネットワーク構成を、選択肢とトレードオフを理解した上で設計できること。

---

## Phase 1: ネットワークの基礎概念

AWS 固有の話は一切出てこない。VPC の設定画面に出てくる用語がすべてここに由来する。

### 1-1. ネットワークの階層構造

- なぜ階層に分けるのか（レイヤ分割の意味）
- TCP/IP の4階層モデルと OSI 参照モデル
- 各レイヤで「宛先」の呼び方が変わる（MAC アドレス / IP アドレス / ポート番号）
- カプセル化 — パケットが層を降りるたびにヘッダが付く

### 1-2. IP アドレスと CIDR

- IP アドレスの正体（32bit の数値）
- サブネットマスクと CIDR 表記（`/24` が何を意味するか）
- ネットワーク部とホスト部
- プライベート IP アドレス（RFC1918）とパブリック IP アドレス
- CIDR の計算感覚（`/16` は何台入るか、`/24` を分割するとどうなるか）

### 1-3. サブネットとルーティング

- サブネットに分ける理由（ブロードキャストドメインの分割、管理・セキュリティ境界）
- ルーティングテーブルの読み方（宛先 → 次の転送先）
- デフォルトゲートウェイと `0.0.0.0/0`
- ロンゲストマッチ（最長一致）の原則

### 1-4. L2 と L3 — スイッチとルータ

- L2（データリンク層）: MAC アドレス、スイッチ、同一セグメント内の通信
- ARP — IP アドレスから MAC アドレスを引く仕組み
- L3（ネットワーク層）: ルータ、セグメントをまたぐ通信
- 「同じサブネット内の通信」と「サブネットをまたぐ通信」で起きることの違い

### 1-5. トランスポート層 — TCP と UDP

- ポート番号の役割（どのプロセスに届けるか）
- TCP: 3ウェイハンドシェイク、コネクション、再送、順序保証
- UDP: コネクションレス、低オーバーヘッド
- コネクションの「状態」とは何か（ステートフルの前提知識）

### 1-6. NAT

- NAT が生まれた理由（IPv4 アドレス枯渇）
- NAPT / IP マスカレード（ポート番号で多重化する仕組み）
- なぜ NAT 越しだと外部から接続を張れないのか
- ソース NAT と デスティネーション NAT

### 1-7. DNS

- 名前解決の流れ（リゾルバ → ルート → TLD → 権威サーバ）
- レコードタイプ（A / AAAA / CNAME / NS / MX / TXT）
- TTL とキャッシュ
- 内部 DNS と分割ホライズン（同じ名前で内外に別の答えを返す）

### 1-8. ファイアウォールとステート

- パケットフィルタリングの基本
- **ステートレス** と **ステートフル** の違い — なぜ戻りの通信を明示的に許可する必要がある/ない のか
- 「送信元 / 宛先 / プロトコル / ポート」の4つ組

## Phase 2: VPC の中核

Phase 1 の概念が AWS でどう実装されているかを対応づけていく。

### 2-1. VPC とは何か

- 「論理的に隔離された仮想ネットワーク」の実体（`compute-isolation/` の VPC オーバーレイ / Hyperplane と接続する話）
- VPC の CIDR 設計（サイズ、後から拡張できるか、他 VPC やオンプレと重複させない設計）
- リージョンと VPC の関係

### 2-2. サブネットと AZ

- サブネットは AZ に閉じる（VPC はリージョン全体、サブネットは AZ 単位）
- パブリックサブネット / プライベートサブネットの定義（実は「ルートテーブルの違い」でしかない）
- AWS が各サブネットで予約している5つの IP
- マルチ AZ 設計の基本形

### 2-3. ルーティングとゲートウェイ

- ルートテーブルとサブネットの関連付け
- **Internet Gateway (IGW)** — パブリックサブネットの正体
- **NAT Gateway** — プライベートサブネットから外へ出る仕組み、コストとスループット
- **Egress-Only Internet Gateway** — IPv6 での NAT 相当
- Local ルート（VPC 内は必ず通る）

### 2-4. IP アドレスと ENI

- **ENI（Elastic Network Interface）** — 仮想 NIC の実体（`compute-isolation/` Q10 の続き）
- プライベート IP / パブリック IP / Elastic IP の違いと挙動
- EC2 / Lambda / Fargate それぞれで ENI がどう割り当たるか
- IP アドレス枯渇問題（特に EKS / Fargate 大規模構成）

### 2-5. セキュリティグループとネットワーク ACL

- **セキュリティグループ** = ステートフル、ENI に付く、許可のみ
- **ネットワーク ACL** = ステートレス、サブネットに付く、許可と拒否
- なぜ2種類あるのか、実務でどう使い分けるか
- セキュリティグループを送信元に指定する書き方（IP を書かない設計）

### 2-6. VPC 内の DNS

- `enableDnsSupport` / `enableDnsHostnames`
- VPC 内リゾルバ（`.2` アドレス）の役割
- Route 53 Private Hosted Zone
- Route 53 Resolver（Inbound / Outbound Endpoint）— オンプレとの名前解決連携

### 2-7. VPC のフロー可視化

- VPC Flow Logs（何が記録され、何が記録されないか）
- Reachability Analyzer / Network Access Analyzer — 疎通しない原因の切り分け

## Phase 3: VPC をまたぐ接続

「設計に活かす」という目的にとって本命のフェーズ。

### 3-1. VPC Peering

- 1対1の接続、トランジティブ（推移的）ルーティングができない制約
- CIDR 重複時に詰む話
- ピア数が増えると N² になる問題

### 3-2. Transit Gateway

- ハブ&スポーク型で N² 問題を解決する
- ルートテーブルによるセグメント分離（本番 / 開発を通さない設計）
- アタッチメント（VPC / VPN / Direct Connect / Peering）
- コスト構造（アタッチメント課金 + データ処理課金）

### 3-3. PrivateLink / VPC Endpoint

- **Gateway Endpoint**（S3 / DynamoDB）— ルートテーブルに書く方式
- **Interface Endpoint**（PrivateLink）— 自 VPC に ENI が生える方式
- PrivateLink の実体（NLB + Hyperplane、`compute-isolation/` の知識と直結）
- CIDR が重複していても繋がる理由
- SaaS 提供側としての Endpoint Service の作り方
- コスト（Endpoint 時間課金 + データ処理課金）と、NAT Gateway 経由との比較

### 3-4. VPC Lattice

- サービス間通信をネットワークではなく「サービス」の単位で繋ぐ考え方
- Transit Gateway / PrivateLink との棲み分け
- 認証（IAM ベースの認可）をネットワーク層に持ち込む発想

### 3-5. オンプレ接続

- **Site-to-Site VPN** — IPsec、コスト安、帯域とレイテンシは公衆網依存
- **Direct Connect** — 専用線、Virtual Interface（Private / Public / Transit）、冗長構成
- Direct Connect Gateway
- どちらを選ぶかの判断軸（帯域 / レイテンシ安定性 / コスト / 構築リードタイム）

## Phase 4: ロードバランシングとトラフィック制御

### 4-1. ELB の種類と使い分け

- **ALB**（L7）— パスやホストによるルーティング、認証統合
- **NLB**（L4）— 静的 IP、超低レイテンシ、PrivateLink の土台
- **GWLB**（L3）— セキュリティアプライアンスの挿入
- クロスゾーン負荷分散とその課金

### 4-2. 名前解決によるトラフィック制御

- Route 53 のルーティングポリシー（シンプル / 加重 / レイテンシ / 位置情報 / フェイルオーバー）
- ヘルスチェックと DNS フェイルオーバーの限界（TTL の壁）
- Global Accelerator との違い（Anycast IP でネットワーク層から誘導する）

### 4-3. エッジ

- CloudFront とオリジンの関係、Origin Access Control
- AWS WAF / Shield の位置づけ

---

## Phase 5: 設計パターンとハンズオン

### 5-1. 典型的な構成パターン

- 3層構成（Public / Private / Isolated サブネット）
- マルチアカウント + Transit Gateway による集約構成
- インスペクション VPC（全通信を検査装置に通す）
- 完全プライベート構成（NAT Gateway なし、すべて VPC Endpoint 経由）

### 5-2. ハンズオン

- Terraform / CDK で VPC 一式を構築
- プライベートサブネットの EC2 に SSM Session Manager で入る（踏み台なし構成）
- VPC Endpoint 経由で S3 にアクセスし、Flow Logs で経路を確認
- Reachability Analyzer で意図的に壊した構成のトラブルシュート
