### 📝 深掘りメモ（2026-06-19）— Rust never型 `!` と「型の値の個数」

#### 0. 前提：型を「取りうる値の個数」で見る
- `bool` = 2値、`u8` = 256値、`()` = **1値**、`!` = **0値**。この「値が何個あるか」という見方がRustの型システムを掴む鍵。

#### 1. `()`（ユニット型）とは
- **「中身のない、1個だけの値を持つ型」**。型でもあり値でもある（唯一の値が `()`）。「意味のある情報を持たない」を表す。
- **Go対応**：Goの「戻り値なし関数」= Rustでは「`()` を返す関数」。`fn f() {}` は `fn f() -> ()` の省略。Goの空構造体 `struct{}` に近い。
- **頻出場所**：
  - `let x = println!("hi");` → `x: ()`（`println!` は `()` を返す）
  - セミコロンで終わるブロックの値は `()`
  - **`Result<(), Error>`**＝「成功時に返すデータはないが失敗はしうる」。Goの `func() error`（成功=nil）に対応する超定番パターン。`Ok(())` で成功を返す。

#### 2. never型 `!` とは
- **「値を1個も持てない型（0値）」**。役割は「この式は**値を返さず制御フローから抜ける（戻ってこない）**」をコンパイラに伝えること。
- `!` を返す式：`panic!()` / `unreachable!()` / `todo!()` / `return` / `break` / `continue` / `process::exit()` / `loop {}`。
- **便利な性質**：値がないので**どんな型にも化けられる**。だから `match` の腕で型が揃わなくても通る：
  ```rust
  let x: i32 = match r { Ok(v) => v, Err(_) => panic!() }; // panic! は ! → i32 に化ける
  ```
- **Go差分**：Goは「戻らない」を型で表せない → `log.Fatal()` の後にダミーの `return 0` を書かされる。Rustは `!` のおかげでそのダミーが不要。

#### 3. なぜ9年かかったか — fallback（推論のデフォルト倒し先）問題
- 型として導入するRFC自体は2018年頃からあったが、「`!` を型名として書ける」最後の一歩が止まっていた。原因は **fallback**。
- **fallback**＝`!` としか繋がっていない推論変数が宙ぶらりんになり、具体型を埋める必要が出たときに何に倒すかの規則。**昔は `()`、これからは `!`**。
- 普段は**不可視**。`!`しか制約のない推論変数が**具体型を要求された瞬間**（トレイト解決・メソッド呼び出し）にだけ差が出る。
- **危険だった本丸（`mem::zeroed`）**：
  ```rust
  let x = if false { unsafe { std::mem::zeroed() } } else { return };
  ```
  `zeroed::<T>()` の `T` は `!` としか繋がらない推論変数。`()` fallback → `T=()` で全ビット0は正当な値＝無害。`!` fallback → `T=!`＝**存在しない値を生成＝即UB**。デフォルトを素直に切り替えると無害コードが突然UB化する。
- → 専用lint `never_type_fallback_flowing_into_unsafe` を用意し、**Rust 2024 editionの境界で段階移行**。この「地雷を踏ませずデフォルトを切り替える」作業が長期化の主因。

#### 4. 今回の安定化（TWIR #656でFCP入り）で変わること
- `!` を**型注釈として一般の位置で書けるようになる**。
- fallback が全エディションで `!` に統一され推論挙動が一貫。
- `#![feature(never_type)]` が外れ **nightly不要で正式に**使える。
- 性格：新機能というより「**nightlyに長年残った言語の最後のピースの正式採用**」。普段のコードが急に変わるわけではなく、`panic`/`return` 周りの型の辻褄合わせが正式な型で裏付けられた節目。
- 関連：`Result<T, !>`（絶対に失敗しないResult）も `!` を型として書く話で繋がる。
