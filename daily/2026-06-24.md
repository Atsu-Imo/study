## 🧠 今日の深掘りメモ

### ハーネスループ（"The Coming Loop" / Armin Ronacher）
- **定義**: エージェントが「完了」と言ったところで止めず、外側のループ(ハーネス)が結果をシグナルで評価し「もう一周回すか」を判断し続ける仕組み。1周ごとに 継続/メッセージ注入/コンテキスト変えてやり直し/別エージェントへ委譲。シグナルは完璧な合否でなく「次の一周を回せる程度」でよい。
- **使える/使えないを分ける唯一の基準**: **verifier(正しさを機械判定する手段)を、人間が見なくても回る形でコード化できるか**。ボトルネックはモデルの賢さではなく「検証の安さと正しさ」。だから強いモデルが出ても解決しない種類の制約。
- **乗せていい（前者寄り）**: コード移植 / テスト付きリファクタ / 性能チューニング(ベンチが数値で出る) / 使い捨ての調査・スキャン。共通点は「正解が外部にある or 成果が使い捨て」＋「1周のコストが低い」。**品質はテスト(verifier)の品質で頭打ち**になる点が手綱。
- **人間が手綱を握る**: 新規の中核ロジック(正解が存在しない) / 設計判断・API の使い勝手(機械が合否を出せない) / E2E が遅く不安定でシグナルが信用できない。
- **判断の一言**: 「正しさを、自分が見なくても回る形でコード化できるか?」 Yes→ループ / No→人間。
- 「今はループの時代」というハイプは「verifier を作れるタスクで効く」を「何にでも効く」にすり替えている。万人向けではない、という当初の懐疑は妥当。

### Algernon の脆弱性と位置づけ
- **CVE-2026-48126 (CVSS 8.2 / High, 修正版 1.17.8)**: `--domain`(または `--letsencrypt`)起動時、配信ディレクトリを `--dir` + **クライアント送信の Host ヘッダ** で `filepath.Join` し検証なし。`Host: ..` で1階層上に出られ、任意ファイル読み取り＋ディレクトリ列挙、さらに `.lua` があればサーバサイド実行まで届く。
- **根因(Go的教訓)**: ①Host ヘッダは詐称可能な入力 → パス解決に使うな。②`filepath.Join` はクリーンにするだけで**ベース配下への閉じ込めは保証しない** → Join 後に絶対パスがベース配下か明示検証(Rel/HasPrefix)、または Host を許可リスト照合。
- **Algernon の位置づけ**: Apache/Nginx(静的配信+リバースプロキシに徹し、動的処理は外部委譲)と違い、**Lua 実行エンジン＋テンプレ/Markdown/DB を1バイナリ内蔵した“アプリ寄り”の全部入り**。近い対比は Caddy + アプリ実行。この内蔵構造ゆえ、パストラバーサルが「読み取り」で止まらず「実行」まで化けやすい。小規模/プロトタイプ向きで、大規模前段プロキシの置き換えではない。
