### 🔬 深掘りメモ: AWSのAIワークロード向け新機能（2026-07-14）

同日発表の3件。**GuardDuty と Security Hub は対の設計**（脅威検知 ⇄ 資産棚卸し）、Lambda のは開発者向けで毛色が違う。

#### ① Amazon GuardDuty AI Protection —「攻撃の検知」
- **何か**: GuardDuty（AWS環境の脅威検知サービス）に、AI固有の攻撃検知を追加したもの。対象は **Bedrock / SageMaker**。
- **検知する脅威**: ①異常なモデル呼び出し（Anomalous Model Invocations）②コスト搾取攻撃（大量GPU/トークンを消費させる金銭的DoS）③プロンプトインジェクション（**Bedrock Guardrails 連携で精度向上**）。
- **どう使う**:
  - データソースは **CloudTrail の management/data events**。→ **エージェント・サイドカー不要**、ログ分析ベースで有効化できる。
  - 有効化は GuardDuty または Security Hub コンソールから。AWS Organizations で全メンバーアカウントに一括展開可。
  - 検知結果は **Security Hub に集約**される。
  - 既存 GuardDuty 顧客は **30日間無料トライアル**。リージョンは Regional Services List を確認。

#### ② AWS Security Hub AI inventory —「何が動いているか把握」
- **何か**: 組織内のAI資産を継続的に棚卸しする機能。**シャドーAI対策**が主眼。①で検知する前提の「地図」にあたる。
- **3つの発見経路**:
  - マネージドAI（AWS Config）→ Bedrock / Bedrock AgentCore / SageMaker
  - 自前ホスト（Inspector の SBOM解析）→ EC2・ECR上の推論エンドポイント・モデル（**Ollama / vLLM / Hugging Face TGI** 等）
  - 外部依存（GuardDuty の DNSテレメトリ）→ EC2から叩いている**第三者モデルAPI**（データ流出リスクの可視化）
- **どう使う**:
  - **Security Hub Essentials に無償で込み・追加の有効化操作も不要**。Security Hub が動く全商用リージョンで利用可。
  - account / resource type / discovery method / model identity でフィルタ・グループ化でき、各資産がセキュリティ検知と紐づく。
- **①との関係**: inventory＝「何があるか（地図）」／ AI Protection＝「何が起きているか（センサー）」。Security Hub ダッシュボードで資産＋脅威を一元的に優先度付けする設計。

#### ③ AWS Lambda one-click coding agent setup —（開発者向け）
- **何か**: Lambdaコンソールに、AIコーディングエージェントへ **AWS Serverless skills + Serverless MCP server** を自動セットアップさせるプロンプトを用意。セキュリティではなく開発体験の話。
- **対応エージェント**: Claude Code / Kiro / Cursor / GitHub Copilot / Codex / Devin / OpenCode。
- **含まれるもの**: Serverless skills、Lambda特化3スキル（MicroVM / Managed Instances / Durable functions）、MCPサーバ設定、AWSサインイン用スキル。
- **どう使う**: Lambdaコンソール上のプロンプトを実行 → エージェントに build/test/deploy まで任せる。AWSがMCPを公式の統合口として標準化していく流れの一環。
