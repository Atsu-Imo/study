## 📝 深掘りメモ

### AWS Lambda セルフマネージドS3コードストレージ

**何が変わって、何が変わらないか（ここが誤解ポイント）**

効くのは**アカウント単位の合計クォータ**であって、**関数1個あたりの上限ではない**。

| | 従来（COPY / デフォルト） | 新（REFERENCE） |
|---|---|---|
| コードの実体 | Lambda管理ストレージに**コピーを保存** | 自分のS3バケットを**直接参照**（コピーしない） |
| アカウント合計クォータ | 消費する（枠は75GB→**300GB**に拡大） | **消費しない**（S3容量が上限＝実質無制限） |
| 1関数の.zipサイズ | 250MB（解凍後） | **250MBのまま変わらず** |
| コンテナイメージ | ECR | 対象外（従来どおりECR、最大10GB） |

→ 効くのは「関数を大量に持っていて300GB枠が苦しい」「S3をアーティファクトの単一の真実源(source of truth)にしたい」ケース。**1個の巨大な関数を作れる機能ではない**。

**仕組み（コールドスタートには効かない）**

- **毎回のコールドスタートでS3を読むわけではない**。作成/更新時にLambdaが内部の最適化表現を作り、以降はそれを使う。→ 実行時レイテンシは基本変わらない。
- 短縮されるのは**作成/更新後のアクティベーション時間**（コピー工程が消えるぶん）。
- Lambdaは**定期的にS3ソースを再アクセスして再最適化**する。→ **S3オブジェクトを消すと関数が `Inactive` に落ちる**。「デプロイしたらS3から消してOK」ではない点が最大の運用上の罠。

**使い方の勘所**

- **S3バージョニング必須**。`S3ObjectVersion` でどのバージョンを使うか追跡する。
- **罠**: `update-function-code` で `S3ObjectStorageMode` を**省略すると毎回 COPY に戻る**。CI/CDでは常に明示。
- **IAM はバケットポリシー**で `lambda.amazonaws.com`（サービスプリンシパル）に `s3:GetObject` / `s3:GetObjectVersion` を付与。`aws:SourceArn` で関数を絞る。実行ロールに付けるのではない点に注意。
- **コンソールのコードエディタは Reference モードで使えない**。編集はS3の.zip差し替え→update。
- .zip専用（コンテナは対象外）。Glacier系以外の全ストレージクラス対応。クロスアカウント/クロスリージョン参照も可（別リージョンは転送料）。

**似て非なる機能**: **S3 Files（2026-04）** はS3を**ファイルシステムとしてマウントして実行時にデータを読む**機能で別物。今回はデプロイパッケージ（コード）の置き場所の話。250MB超が要るなら引き続きコンテナ（ECR）が答え。

### Pomerium zip-bomb DoS（CVE-2026-50285 / High）

**Pomerium とは**: ゼロトラストのリバースプロキシ。アプリの**手前**に立って認証・認可を担う。ここが落ちると背後のサービスが丸ごと不通になる。

**何が起きたか**

- HPKE のコールバック処理で、受け取った **zstd 圧縮データを上限なしで解凍**していた。
- 攻撃者は**認証前(pre-auth)**にこの経路を叩ける＝認証不要で誰でも撃てる。
- **小さな圧縮ペイロード（数KB）が解凍後に数GB**に膨らむよう細工できる（zip-bomb / decompression bomb）。数発でメモリ枯渇→プロセス死 = DoS。

**本質**: 解凍処理は**解凍後サイズが入力から予測できない**。攻撃者が圧縮比を操れるので、**解凍後の上限を決めずに解凍する = 常に穴**。`Content-Length`（圧縮後サイズ）を見ても無意味。

**Go での教訓**

```go
// ❌ 危険: 解凍後サイズが無制限
data, _ := io.ReadAll(zr)          // zr は zstd/gzip.Reader

// ✅ 上限を決めて、超えたらエラーにする
lr := io.LimitReader(zr, maxDecompressedBytes)  // 例: 10MB
data, err := io.ReadAll(lr)
if int64(len(data)) >= maxDecompressedBytes {
    return errUncompressedTooLarge   // 上限ちょうど = 切れた可能性 → 拒否
}
```

`io.LimitReader` で**解凍後**のバイト数を縛るのがポイント。外部入力を解凍している箇所すべてに解凍後上限があるか点検する、が持ち帰りどころ。
