- **[How Our Rust-to-Zig Rewrite Is Going](https://rtfeldman.com/rust-to-zig)**（発見層 / lobste.rs・HN 双方でトップ）
  - Roc コンパイラを Rust から Zig へ全面書き直しした 18ヶ月の実測レポート。動機はアリーナアロケータと struct-of-arrays を前提にしたメモリレイアウト制御と、インクリメンタルビルドの速さ。
  - 影響: 数字が面白い。メモリ破壊バグは Zig 版 2件に対し Rust 版 21件（ただし Rust 側の大半は unsafe ではなくミスコンパイル由来）。「Zig の方が優れている」ではなく「コンパイラという特殊な領域では要件が違う」という結論の立て方が誠実で、言語選定の議論に使える。
- **[Amazon S3 removes the 30-day minimum for Standard-IA / One Zone-IA transitions](https://aws.amazon.com/about-aws/whats-new/2026/07/s3-removes-30-day-transitions-standard-ia-one-zone-ia)**
  - これまで Standard-IA / One Zone-IA へのライフサイクル遷移には最低30日の据え置きが必要だったが、撤廃されオブジェクト作成直後から遷移可能になった。
  - 影響: 「作られた瞬間からほぼ読まれない」タイプのデータ（アーカイブ用の中間ファイル、収録後のマスター素材など）で、30日分の Standard 課金を丸ごと削れる。既存のライフサイクルルールを見直す動機になる。
- **[Amazon S3 Event Notifications now include system-generated tags](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-s3-event-notifications-system-generated-tags/)**
  - S3 イベント通知のペイロードにシステム生成タグが含まれるようになり、AWS 側の表現では「数千バケットのイベントを単一の EventBridge ルールでフィルタできる」。
  - 影響: バケットごとにルールを増やしていく運用から抜けられる。バケット数が多い環境ほど効く。
- **[PostgreSQL 19 Beta 2 available in the Amazon RDS Database Preview Environment](https://aws.amazon.com/about-aws/whats-new/2026/07/postgresql-19-beta-2-amazon-rds-database-preview-environment/)**
  - 並列 autovacuum、オンラインでのテーブル再構築、SQL グラフクエリなどを RDS 上で試せる。
  - 影響: 本番投入はまだ先だが、特にオンライン再構築は「VACUUM FULL のためのメンテ枠」を前提にした運用設計を変えうる。

## 🔒 Vulnerabilities & Security
- **[CISA KEV — Oracle E-Business Suite の権限管理不備](https://www.cisa.gov/news-events/alerts/2026/07/15/cisa-adds-two-known-exploited-vulnerabilities-catalog)** — `CVE-2026-46817 / 悪用確認済み`
  - 7/15 に KEV へ追加された2件のうちの1件（もう1件は KNX プロトコルの CVE-2023-4346、アカウントロックアウト機構の不備）。実際の悪用が確認されている。
  - 影響: 連邦機関の是正期限が **本日 7/17**。Oracle EBS を持っているなら最優先。なお 7/16 付の新規追加はなし。
- **[mcp (Python SDK) — WebSocket server transport lacks Host/Origin validation](https://github.com/advisories)** — `High`
  - MCP の Python SDK の WebSocket サーバトランスポートが Host / Origin ヘッダを検証していない。
  - 影響: ローカルで動く MCP サーバに対し、ブラウザ経由の cross-site WebSocket hijacking が成立しうる典型パターン。MCP サーバをローカルで立てて使う構成は今まさに増えているところなので、該当バージョンを使っていないか確認したい。
- **[github.com/kumahq/kuma — TLS certificate verification missing when no CA is configured](https://github.com/advisories)** — `Moderate`
  - CA が未設定の場合に TLS 証明書の検証がスキップされる。Go 製のサービスメッシュ。
  - 影響: 「設定漏れが検証無効に fail-open する」種類の実装バグ。中間者攻撃が成立する経路になる。
- **[ArcadeDB — 認可バイパス／RCE クラスタ（複数 advisory）](https://github.com/advisories)** — `High`
  - 7/16 に arcadedb-server / arcadedb-engine に対して6件以上がまとめて公開。クロスDBの IDOR、`DEFINE FUNCTION` の JavaScript 経由でのスクリプティング認可バイパス、トリガスクリプトから `java.lang.*` を叩けることによる RCE、read-only ユーザによるスキーマ変更、`IMPORT DATABASE` 経由の SSRF など。
  - 影響: 単発のバグではなく「認可モデルそのものが穴だらけ」という形。使っているなら一括アップグレード必須。
- **[pheditor — hardcoded default password 'admin'](https://github.com/advisories)** — `Critical`
  - デフォルトパスワードが `admin` にハードコードされ、変更も強制されない。同時にターミナル機能のコマンドサニタイズ不備による RCE（High）も公開。
  - 影響: 2つ合わせると「デフォルト設置＝無認証 RCE」。
