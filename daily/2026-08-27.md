## 🔬 深掘り — Go 1.27 のジェネリックメソッド

出典: [Generic Methods](https://go.dev/blog/generic-methods) / [Go 1.27 is released](https://go.dev/blog/go1.27)

### Q. 「メソッドに型パラメータ」とはどういう意味か

メソッド自身が**新しい型パラメータを宣言できる**ようになった、という意味。

Go 1.18 以降もレシーバの型パラメータを**使う**ことはできた。ただしそれは `List[T]` の `T` を参照しているだけで、メソッドが新しい型変数を導入することはできなかった。

```go
type List[T any] struct{ items []T }

// 1.18〜1.26: T は使えるが、新しい U は宣言できない
func (l *List[T]) Len() int { return len(l.items) }
func (l *List[T]) Map[U any](f func(T) U) *List[U] { ... }  // ← 構文エラー

// 回避策: パッケージスコープの関数に追い出す
func Map[T, U any](l *List[T], f func(T) U) *List[U] { ... }
```

`Map` は本来 `List` の操作なのに、`U` を宣言する場所がないという理由だけでパッケージスコープに出る。結果として呼び出しが内側から外側に読む形になる。

```go
// 関数版: 実行順と読む順が逆
Map(Filter(l, isEven), toString)

// 1.27 のメソッド版: 左から右
l.Filter(isEven).Map(toString)
```

### Q. 具体的にどう使うのか

効くのは「呼び出し側で決まる型が、レシーバの型パラメータでは表現できない」場面。

**1. Map — 戻り値の要素型が呼び出しごとに変わる**

```go
type Seq[T any] struct{ xs []T }

func From[T any](xs []T) Seq[T] { return Seq[T]{xs} }

func (s Seq[T]) Filter(pred func(T) bool) Seq[T] {
	out := make([]T, 0, len(s.xs))
	for _, x := range s.xs {
		if pred(x) {
			out = append(out, x)
		}
	}
	return Seq[T]{out}
}

// 1.27: メソッドが新しい型パラメータ U を宣言できる
func (s Seq[T]) Map[U any](f func(T) U) Seq[U] {
	out := make([]U, 0, len(s.xs))
	for _, x := range s.xs {
		out = append(out, f(x))
	}
	return Seq[U]{out}
}

func (s Seq[T]) Slice() []T { return s.xs }
```

```go
// 1.27
names := From(users).
	Filter(func(u User) bool { return u.Active }).
	Map(func(u User) string { return u.Name }).
	Slice()

// 1.26 以前: Map だけ関数なので、ここで読む向きが反転する
names := Map(From(users).Filter(isActive), userName).Slice()
```

**2. GroupBy — キーの型が呼び出し側で決まる**

```go
func (s Seq[T]) GroupBy[K comparable](key func(T) K) map[K][]T {
	m := make(map[K][]T)
	for _, x := range s.xs {
		k := key(x)
		m[k] = append(m[k], x)
	}
	return m
}
```

```go
byDept := From(users).GroupBy(func(u User) string { return u.Dept })
byYear := From(users).GroupBy(func(u User) int { return u.JoinedAt.Year() })
```

同じメソッドが `K = string` と `K = int` で別々に実体化される。`Seq[T]` の `T` は `User` のままなので、レシーバ側の型パラメータでは書けない。

**3. 型付きレジストリ / DI コンテナ**

```go
type Container struct{ m map[reflect.Type]any }

func (c *Container) Get[T any]() (T, bool) {
	v, ok := c.m[reflect.TypeFor[T]()]
	if !ok {
		var zero T
		return zero, false
	}
	return v.(T), true
}
```

```go
db, ok := c.Get[*sql.DB]()
```

1.26 以前は `Get[*sql.DB](c)` というパッケージ関数にするしかなかった。`context.Value` の型なしアクセスを置き換える用途でよく出てくる形。

**4. エラーを畳み込むパイプライン**

```go
type Res[T any] struct {
	v   T
	err error
}

func (r Res[T]) Then[U any](f func(T) (U, error)) Res[U] {
	if r.err != nil {
		var zero U
		return Res[U]{zero, r.err}
	}
	u, err := f(r.v)
	return Res[U]{u, err}
}

func (r Res[T]) Unwrap() (T, error) { return r.v, r.err }
```

```go
item, err := Ok(req).
	Then(fetch).        // *http.Request  -> *http.Response
	Then(readBody).     // *http.Response -> []byte
	Then(decode[Item]). // []byte         -> Item
	Unwrap()
```

書けるようになるが、Go の慣習からは外れる（各段で `if err != nil` を書くほうが標準的）。Rust の `?` に相当するものが手に入ったわけではない。

### Q. 制約は何か

**具象型のメソッドにしか付けられない。** インターフェースはジェネリックメソッドを宣言できない。

```go
type Mapper interface {
	Map[U any](f func(int) U) []U  // ← コンパイルエラー
}
```

理由は Go のコンパイルモデル。インターフェース経由の呼び出しは実行時のディスパッチテーブル越しになるため、コンパイラは「どの型引数で実体化されるか」をパッケージ境界を越えて知る必要がある。全パッケージの全呼び出し箇所を見ない限り列挙できないので、あり得る型引数すべてに対してコードを生成するしかなくなる。これを避けて禁止した。

結果として、ジェネリックメソッドは**具象型の中に閉じた記述の利便性**であって、ポリモーフィズムの手段ではない。`Seq[T]` を `Mapper` として受け渡す、といった抽象化はできない。

Rust が単相化前提で `dyn Trait` にジェネリックメソッドを許さない（object safety）のと、動機はほぼ同じ。
