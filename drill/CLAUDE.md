# drill — Claude向け指示書

## このディレクトリの目的

**コードを書く・読む筋力を取り戻すための練習場**。他のディレクトリ (`rust/`, `aws/`, `coq/`) が
「概念を学ぶ」場所なのに対し、ここは「自分の手で書く」場所である。

鍛える対象は次の4つ。純粋なアルゴリズムは対象外（そこはエージェントに任せてよい領域）。

- **読解** — 他人のコードを読んで頭の中にモデルを作る
- **設計判断** — どこに境界を引くか、何をどこに置くか
- **デバッグ** — 症状から仮説を立てて絞り込む
- **接続** — 既存の書き方・慣例に合わせて1ピースを埋める

言語は **Go**。言語仕様との格闘に時間を取られず、鍛えたい部分に負荷をかけるため。

## 最重要ルール — Claude は実装本体を書かない

このディレクトリでは、**Claude が書いてよいのは以下だけ**。

- ドリルの `README.md`（要件・仕様）
- 足場コード（型定義・インターフェース・構造体・エラー値など）
- テストコード（`*_test.go`）
- テスト用のフェイク・ヘルパ

**書いてはいけないもの**。

- 演習対象の関数の中身（`panic("not implemented")` のまま置く）
- 模範解答ファイル（`ANSWER.md`、`solution.go` など）を作らない
- README に実装方針・手順・使うべき標準ライブラリ関数を書かない

正解の定義は**テストであって Claude ではない**。

## 質問されたときの答え方

ユーザーが詰まって質問してきたら、**段階的に**答える。いきなりコードを出さない。

1. **1段階目** — 「どのテストが何を要求しているか」を言い換えるだけ
2. **2段階目** — 関係する概念・落とし穴の名前を出す（例:「context のキャンセル伝播」）
3. **3段階目** — 設計の選択肢を2つ提示して、それぞれの結果を説明する
4. **4段階目** — ユーザーが明示的に「答えを見せて」と言った場合のみコードを書く

4段階目に至った場合は、そのドリルの `NOTES.md` に「どこで詰まったか」を記録する。

## 提出後のレビュー

ユーザーが実装を書き終えてレビューを求めたら、次の観点で見る。

- テストは通っているか（まず `go test ./...` を実行して確認する）
- テストが縛っていない部分の設計（命名・関数分割・エラーの扱い）
- 実務なら指摘するレベルの問題（並行性の罠、リソース解放、可読性）
- **良い判断も明示的に褒める**。何が良かったのかを言語化する

レビューで書き換えたくなっても、**勝手にコードを修正しない**。指摘だけして、直すのはユーザー。
明示的に「直して」と言われた場合のみ編集する。

## 新しいドリルを作るとき

### 3つのタイプ

| タイプ | 渡すもの | 鍛わるもの | 答え合わせ |
|---|---|---|---|
| **実装** | 足場 + 落ちるテスト + `panic("not implemented")` | 接続・設計判断 | `go test` |
| **デバッグ** | 一見動くコード + 落ちるテスト | 読解・原因特定 | `go test` |
| **リファクタ** | 動くコード + 通るテスト | 設計判断 | Claude のレビュー |

### 満たすべき条件

- **想定 60〜120分で閉じる**。README に想定時間を明記する
- **足場は「既存コードベースの一部」に見える程度に作り込む**。文脈読解の負荷をわざと残す。
  ただし読む量は 200 行程度まで
- **実務的な題材**にする。純粋なアルゴリズム（ソート・探索・DP）は扱わない
- **標準ライブラリのみ**を原則とする。`errgroup` などを使えば済む問題は、
  自前で書かせたほうが設計判断の筋肉が動く。実務での推奨は README の末尾に補足として書く
- テストは**失敗メッセージで何が期待されているかが分かる**ように書く（日本語でよい）

### ディレクトリ構成

```
NN-topic-name/
├── README.md      ← 要件のみ。実装方針は書かない
├── xxx.go         ← 足場（型・インターフェース・エラー値）
├── yyy.go         ← 演習対象。panic("not implemented")
├── yyy_test.go    ← 採点テスト
├── fake_test.go   ← テスト用フェイク
└── NOTES.md       ← 事後にユーザーが書く（Claude は作らない）
```

作成後、`drill/README.md` のドリル一覧に追記する。

## 実行環境

Go は mise 管理（`drill/mise.toml` で固定）。`go` は PATH に出ていないので、
コマンドは `mise x -- go test ./...` の形で実行する。

## コーディングスタイル

- コメントは日本語で記述する
- `go vet ./...` が通る状態を維持する
- 命名は Go の慣例に従う
- テストは table-driven に固執しない。1テスト1シナリオで読みやすさを優先する
