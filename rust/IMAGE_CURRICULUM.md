# 画像フォーマット学習カリキュラム — Rustで作る PNG デコーダ

## コンセプト

「`.png` ファイルをダブルクリックすると画像が表示される」——
その間に何が起きているのかを、**PNG デコーダを自分で書くことで理解する**カリキュラム。

`NETWORK_CURRICULUM.md` が「ネットワーク上の登場人物を1人ずつ作る」だったのに対し、
こちらは **1つのバイナリフォーマットを入口から出口まで貫通させる**のが狙い。

ゴールは「PNG ファイルのバイト列 → 画面に出せるピクセル配列」を
外部クレートなしで（zlib 展開まで含めて）自力で通すこと。

## 全体像 — PNG ファイルがピクセルになるまで

```
sample.png (ファイル上のバイト列)
  │
  │ ① シグネチャ確認 "\x89PNG\r\n\x1a\n"
  │   チャンク単位に切り分ける (length + type + data + CRC)
  ▼                                             ← img-01 で実装
┌──────┬──────┬──────┬──────┬──────┐
│ IHDR │ tEXt │ IDAT │ IDAT │ IEND │  チャンクの列
└──┬───┴──────┴──┬───┴──┬───┴──────┘
   │              └──────┘
   │ ② IHDR を読む                              ← img-02 で実装
   │   幅・高さ・ビット深度・カラータイプ
   │   → 「1ピクセル何バイトか」が確定する
   ▼
   │ ③ 全 IDAT のデータを連結 → zlib ストリーム
   │   inflate (Deflate 展開)                    ← img-03 で実装
   ▼
┌────────────────────────────────┐
│ フィルタ済みスキャンライン列      │
│ [f][pixel][pixel]... ← 1行目    │  各行の先頭1バイトが
│ [f][pixel][pixel]... ← 2行目    │  フィルタタイプ (0〜4)
└──────────────┬─────────────────┘
   │ ④ フィルタ復元                             ← img-04 で実装
   │   None/Sub/Up/Average/Paeth の逆演算
   ▼
┌────────────────────────────────┐
│ 生のピクセル配列 (RGB/RGBA...)  │  → PPM で書き出して目視確認
└────────────────────────────────┘
                                                 ← img-05 で統合
```

## 各トピックの詳細

### img-01: チャンクパーサ ✅

- **作るもの**: PNG を読み込み、チャンクを一覧表示して CRC を検証するダンプツール
- **理解できること**:
  - PNG は「シグネチャ + チャンクの列」という単純な入れ物である
  - チャンクは `長さ(4) + 型(4) + データ + CRC(4)` の固定フォーマット
  - チャンク型の**大文字小文字がフラグとして意味を持つ** (必須/補助、公開/私用、コピー可否)
  - 未知のチャンクを安全に読み飛ばせる設計になっている理由
  - CRC-32 を自前実装して整合性を検証する

### img-02: ヘッダ解釈器 ✅

- **作るもの**: IHDR を解釈し「1ピクセル何バイトか」「展開後のバイト数はいくつか」を計算する
- **理解できること**:
  - カラータイプ 0/2/3/4/6 (グレースケール、真色、パレット、+アルファ) の違い
  - ビット深度 1/2/4/8/16 — 1ピクセル1バイト未満のケース
  - PLTE / tRNS / gAMA など補助チャンクが何をしているか
  - 「幅×高さ×バイト数」から展開後サイズを予測する (= 展開爆弾の防御にも効く)

### img-03: zlib/Deflate 展開器

- **作るもの**: IDAT の中身 (zlib ストリーム) を自前で inflate する
- **理解できること**:
  - PNG の圧縮は PNG 独自ではなく **zlib (Deflate) をそのまま使っている**
  - Deflate = LZ77 (繰り返しの参照化) + ハフマン符号 (頻出パターンを短いビットに)
  - 固定ハフマン / 動的ハフマンブロックの違い
  - ビット単位で読むパーサの書き方 (バイト境界に揃わない世界)
- **難易度**: このカリキュラム最大の山。ここだけ2〜3ステップに分割する可能性あり

### img-04: フィルタ復元器

- **作るもの**: 展開後のスキャンラインからフィルタを剥がして生ピクセルにする
- **理解できること**:
  - PNG が圧縮前に行う「前処理」——**隣接ピクセルとの差分を取る**発想
  - None / Sub / Up / Average / Paeth の5種と、それぞれの逆演算
  - なぜ差分を取ると zlib がよく効くのか (グラデーションが 0 の列になる)
  - Paeth 予測子 = 左・上・左上のうち「最も自然な予測」を選ぶ

### img-05: PNG デコーダ完成版

- **作るもの**: 01〜04 を結合し、PNG → PPM (単純なテキスト画像形式) に変換するツール
- **理解できること**:
  - 全工程が1本のパイプラインとして繋がる
  - パレット画像の展開 (インデックス → RGB)
  - Adam7 インターレース (7回に分けて粗→細で送る仕組み)
  - 実際に画像ビューアで開いて「デコードできた」を目で確認する

## 使用クレート方針

**原則、外部クレートは使わない** (`std` のみ)。

このカリキュラムの目的は「中で何が起きているか」なので、
`png` クレートや `flate2` を使うと学ぶものが何も残らない。

ただし img-03 で自前 inflate に詰まった場合は、
`flate2` で先に 04/05 を通してから 03 に戻る、という順序変更を許容する。

## 難易度カーブ

- **01**: 入門 — バイナリの切り分けと CRC。`net-03` (DNS) のバイナリパースと同レベル
- **02**: 入門〜中級 — 仕様の読み解きが中心
- **03**: 上級 — ビット単位のパースとハフマン木。ここが本丸
- **04**: 中級 — アルゴリズム自体は素直だが、境界条件 (1行目・1列目) が罠
- **05**: 統合 — 繋ぎ込みとエッジケース
